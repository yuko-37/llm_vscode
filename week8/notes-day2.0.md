1. Суть (что это и зачем нужно?)
Создать векторную БД и заполнить её тренировочными данными - это подготовка к RAG.
Этот этап решает проблему векторизации и хранения текстов, чтобы LLM могла быстро искать и использовать релевантные фрагменты при герерации ответов.


2. Как работает (основная идея)
Идея: выгрузить подготовленные данные, батчами закодировать в вектора и сохранить в векторную бд.
    состоит из:
        train.pkl: данные
        pickle: библиотека для выгрузки данных
        SentenceTransformer(all-MiniLM-L6-v2): эмбеддинговая модель для преобразования текста в вектор, размерность: 384
        chromadb: векторная база данных для хранения embeddings + метаданных

— Как они взаимодействуют?
`train.pkl
 -> pickle train.pkl -> texts.
 -> SentenceTransformer.encode -> emeddings
 -> chromadb.add -> vector DB
`
3. Пример (в действии)
    1. выгрузить данные из train.pkl в объект - список dict
    2. обрезать данные, убрать лишний текст
    3. разбить данные на батчи по 1000
    4. каждый батч закодировать в список векторов
    5. создать метаданные
    6. сохранить батч в бд


4. Проверка понимания
Вопросы на собеседовании:
    Вопрос 1. Что такое эмбеддинговая модель?
    Это модель, которая обучена преобразовывыть текст в плотный многомерный вектор, отражающий смысловые связи между словами.
    
    Вопрос 2. Что такое векторная бд, для чего она нужна, какие есть векторные бд?
    Это бд, которая хранит векторное представление текста, его метаданные, а также сам текст как часть метаданных. Она используется для поиска по смысловому сходству.
